# PlatformX (MVP)

منصة تدريب عملي في Platform Engineering — نسخة MVP قابلة للتشغيل فورًا.

## اللي موجود دلوقتي

- الصفحة الرئيسية + رحلة المتعلّم + لوحة حالة (status panel)
- صفحة المسارات (DevOps / Platform Engineer / OpenShift Engineer) + صفحة تفاصيل لكل مسار
- صفحة المعامل (نماذج Labs بسيناريوهات وقوائم فحص)
- صفحة تسجيل (`/register`) على خطوتين: تعبئة البيانات، وبعدها كود تحقق من 6 أرقام يتبعت
  على البريد وصالح لمدة **دقيقة واحدة** بالظبط. التسجيل ما يكملش غير بعد التحقق من الكود.
- لوحة تحكم تجريبية (`/dashboard`) بتقرأ آخر تسجيل من الـ localStorage بس (مفيش قاعدة بيانات حقيقية لسه)

## اللي لسه مش موجود (خطوات تالية)

- قاعدة بيانات حقيقية لحفظ المستخدمين (Vercel Postgres / Supabase + Prisma)
- تسجيل دخول حقيقي (NextAuth أو مشابه)
- تنفيذ وفحص آلي فعلي للمعامل (بيئة تنفيذ منفصلة، مش جزء من الـ Next.js نفسه)
- Mentor dashboard وتقييمات حقيقية
- عداد المتعلمين الفعلي (حاليًا أرقام في `lib/data.ts` تقدر تعدّلها يدويًا)

## كود التحقق بالإيميل (OTP)

خطوات التسجيل دلوقتي:

1. المستخدم يعبي الفورم ويضغط **أرسل كود التحقق**.
2. المنصة تولّد كود من 6 أرقام وتبعته على الإيميل، وتفضل صالحة **دقيقة واحدة بالظبط**.
3. المستخدم يكتب الكود؛ لو صح وقبل ما تنتهي الدقيقة، التسجيل يكمل. لو الوقت خلص، لازم يضغط
   **إعادة إرسال الكود** ياخد كود جديد.

### تشغيل إرسال الإيميل فعليًا

من غير إعداد، الكود بيتطبع في الـ terminal بتاعك بس (وبيظهر في الصفحة نفسها تحت
عنوان "وضع تجربة") — عشان تقدر تجرب الفلو كامل من غير ما تحتاج تعمل حساب بريد.

عشان يبعت إيميل حقيقي:

1. اعمل حساب مجاني على [resend.com](https://resend.com) وخد API key.
2. لو شغّال محليًا: انسخ `.env.example` لملف اسمه `.env.local` وحط فيه الـ key.
3. لو على Vercel: من إعدادات المشروع → **Environment Variables** ضيف
   `RESEND_API_KEY` (و`OTP_FROM_EMAIL` لو عايز تغيّر المرسل بعد ما تعمل verify لدومينك).
4. اعمل redeploy، وبعدها الإيميلات هتتبعت فعليًا بدل ما تتطبع في الـ logs.

### ملاحظة عن التخزين

أكواد التحقق **مش متخزنة في ذاكرة السيرفر** — بتتوقّع (HMAC-signed token) وتترجع
للمتصفح، وبيتم التحقق منها في نفس اللحظة من غير ما السيرفر يحتاج يتذكر حاجة من قبل.
ده مقصود ومهم: على Vercel كل طلب ممكن يوصل لـ serverless instance مختلفة، فأي تخزين
عادي في الذاكرة (Map) مش هيشتغل بشكل موثوق بين طلب إرسال الكود وطلب التحقق منه.

**لازم** تضيف متغير `OTP_SECRET` (سلسلة عشوائية طويلة) في `.env.local` محليًا،
وفي Vercel Environment Variables قبل الإطلاق الفعلي — من غيره بيستخدم قيمة افتراضية
مكتوبة في الكود، وهي مش آمنة للإنتاج. تقدر تولّد وحدة بالأمر:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

## تشغيل المشروع محليًا

محتاج [Node.js](https://nodejs.org) نسخة 18 أو أحدث.

```bash
npm install
npm run dev
```

بعدين افتح `http://localhost:3000`.

## الرفع على Vercel

### الطريقة الأسهل (من غير Git) — Vercel CLI

1. ثبّت الأداة:
   ```bash
   npm install -g vercel
   ```
2. من جوه فولدر المشروع:
   ```bash
   vercel
   ```
3. هيسألك أسئلة بسيطة (login بحساب Vercel، اسم المشروع، إلخ) — اقبل الإعدادات الافتراضية.
4. لما يخلص، هيديك رابط `.vercel.app` تقدر تفتحه فورًا.
5. لو عايز رابط إنتاج نهائي بعد كده:
   ```bash
   vercel --prod
   ```

### الطريقة الموصى بها (عشان تقدر تعدّل بسهولة بعد كده) — عن طريق GitHub

1. اعمل repository جديد فاضي على GitHub.
2. من جوه فولدر المشروع:
   ```bash
   git init
   git add .
   git commit -m "PlatformX MVP"
   git branch -M main
   git remote add origin <رابط الـ repo بتاعك>
   git push -u origin main
   ```
3. ادخل [vercel.com](https://vercel.com) → **Add New Project** → اختار الـ repo ده.
4. Vercel هيكتشف إن المشروع Next.js تلقائيًا (مفيش إعدادات إضافية مطلوبة).
5. دوس **Deploy** واستنى دقيقة، وهيديك رابط live.

بعد كده أي `git push` جديد على `main` هيعمل نشر تلقائي.

## ملاحظة مهمة

الأرقام في الصفحة الرئيسية (عدد المتعلمين، المعامل المكتملة...) موجودة في `lib/data.ts`
وهي أرقام بداية توضيحية بس. عدّلها بنفسك، أو لما تضيف قاعدة بيانات حقيقية اربطها بيها
بدل ما تفضل ثابتة.
